# Milk Collection Problem with Incompatibility Constraints (HMCHF)

Based on Caramia & Guerriero, *Interfaces* 40(2), 2010, and the MSO-103 slides.

This project has two parts: the C++ solvers and tools, and a small local web dashboard (`ui/`) that runs them from the browser.

| file | what it is |
|---|---|
| `exact.cpp` | exact solver (proven optimum on small instances) |
| `heuristic.cpp` | ALNS heuristic for larger instances (case-study scale and beyond) |
| `checker.cpp` | independent validator: checks every constraint and recomputes the objective |
| `gen.cpp` | random instance generator (`paper` mode uses the paper's 13-vehicle fleet) |
| `milk_io.h` | the input reader and plan printer shared by the solvers and the checker |
| `run_tests.sh` | compares heuristic and exact on random small instances (all outputs are checked) |
| `edge_tests.sh` | edge-case regression (23 cases x 2 solvers, including input mistakes, plus checker self-tests) |
| `sample.txt` | commented sample input; reference plans are in `sample_out_exact.txt` and `sample_out_heuristic.txt` |
| `big.txt` | a generated paper-size instance (`./gen 7 50 paper`): 50 farms, 13 vehicles |
| `tests/` | generated by `run_tests.sh` (`tN.txt` input, `tN.exact` / `tN.heur` plans). Safe to delete; it is recreated on the next run |
| `plan.txt` | a saved heuristic plan for `sample.txt` (same content as `sample_out_heuristic.txt`), left over from the `> plan.txt` example below |
| `ui/server.py` | stdlib-only Python server for the dashboard |
| `ui/index.html` | the dashboard page (single file, no build step) |
| `ui/HANDOFF.md` | developer notes for the dashboard |

The compiled binaries `exact`, `heuristic`, `checker` and `gen` are Linux executables built from the `.cpp` files. They are rebuilt by the commands below, by `server.py`, or by the test scripts.

## How to run (Linux / macOS / WSL, needs g++ with C++17 and Python 3)

```
cd ~/milk_collection

# 1. build (once, or after changing any .cpp / .h file)
g++ -std=c++17 -O2 -o exact     exact.cpp
g++ -std=c++17 -O2 -o heuristic heuristic.cpp
g++ -std=c++17 -O2 -o checker   checker.cpp
g++ -std=c++17 -O2 -o gen       gen.cpp

# 2. solve a day's input file (copy sample.txt and edit it for your own data)
./exact     < sample.txt                   # proven best plan; small inputs only (about 10 farms)
./heuristic < sample.txt                   # good plan for any size, 2 s by default
./heuristic 10 7 < sample.txt              # run 10 seconds with random seed 7
./heuristic < sample.txt > plan.txt        # save the plan to a file

# 3. check a saved plan against its input
./checker sample.txt plan.txt              # OK <vehicles> <minutes>  |  INFEASIBLE  |  FAIL: reason

# 4. tests (each builds the programs first)
./edge_tests.sh                            # corner cases and checker self-tests
./run_tests.sh 300 0.5                     # 300 random inputs: heuristic vs proven optimum
./gen 7 50 paper > big.txt && ./heuristic 10 < big.txt   # paper-size case: 50 farms, 13 vehicles
```

The solvers print a progress note on the terminal (for example `heuristic: iterations=...`). That note is not part of the plan, and `> plan.txt` does not capture it.

If the `.sh` files say "permission denied", run `chmod +x *.sh` once.

## Web dashboard (localhost)

```
cd ~/milk_collection          # use WSL on Windows (the binaries are Linux programs)
python3 ui/server.py          # then open http://127.0.0.1:8000
```

- `server.py` needs only the Python standard library. On start it compiles `exact`, `heuristic` and `checker` with g++ if a binary is missing or older than its source (`.cpp` or `.h`), then serves the page.
- Use another port with `PORT=8123 python3 ui/server.py`.
- The page has forms for settings, farms, the distance matrix and the fleet. Buttons: Solve, Load sample, Import / Export input .txt, Clear all. Results show as summary cards, a card per vehicle with its route(s), and compartment fill bars. A "Raw solver output" section shows the printed plan, and the checker verdict is shown too.
- Heuristic run time in the UI is limited to 1 to 60 s. The exact solver is cut off after 300 s.
- The server listens on 127.0.0.1 only and has no login. It is meant for local use.
- The page loads its fonts (Inter, Quicksand) from Google Fonts. Without internet it still works but falls back to system fonts.
- Developer notes are in `ui/HANDOFF.md`.

## The model

One day, one depot (node 0), farmers 1..n, milk types 1..m, vehicles 1..V.
- **Vehicles.** A pure truck (`P`) has compartments. A complete vehicle (`C`) has truck compartments plus trailer compartments.
- **One milk type per compartment per day.** A compartment holds any amount up to its capacity.
- **Split pickup is allowed.** A farmer's milk can be divided between several vehicles and compartments.
- **Pure truck:** depot -> farmers -> depot. It may visit any farmer.
- **Complete vehicle:**
  - Its main tour (with the trailer) visits only S_tr farmers.
  - It can park the trailer at the depot or at an S_tr farmer on its own main tour. The truck then runs subtours that visit only S_wt farmers and come back to the parking spot.
  - Trailer compartments take milk only from farmers on the main tour (A8: no truck<->trailer transfer).
  - If used, it must visit at least one S_tr farmer (A4).
- **Tour duration** = sum of travel time + sum of preparation time of the farmers visited. It must be <= the shift T.
- **Objective (lexicographic, as in the paper's Phase I and Phase II):** first the fewest vehicles, then the least total time.

## Input file (plain text, one record per line)

Anything after `#` is a note and is ignored. Columns can be separated by any number of spaces. Names are single words (use `_` instead of spaces). Keywords are not case-sensitive. See `sample.txt` for a fully commented example.

```
SHIFT_MINUTES        480                          how long a vehicle may be out
SPEED_KM_PER_HOUR    60                           average driving speed
MILK_TYPES           High_quality Standard Sanitary   kinds of milk never mixed in one compartment

FARMS
# name     road         stop   High_quality  Standard  Sanitary   (quintals)
  Rossi    trailer_ok   15     30            0         0
  Greco    truck_only   20     0             40        5

DISTANCES_KM                                      km; rows and columns: Depot, then farms in FARMS order
#          Depot  Rossi  Greco                    <- this header line MUST start with #
  Depot    0      40     70
  Rossi    40     0      45
  Greco    70     45     0

FLEET
  Truck_A  truck 37.5 37.5  trailer 37.5 37.5     truck + trailer: compartment sizes of each part
  Truck_B  truck 46.7 46.7 46.7                   a truck on its own
```

- `road`: `trailer_ok` means a truck pulling its trailer can reach the farm (set S_tr). `truck_only` means the trailer must be left behind (set S_wt).
- `stop`: minutes spent at the farm (the paper's preparation time).
- The number of farms, milk types and vehicles is simply the number of entries; nothing needs counting.
- **The distance header line must start with `#`.** The matrix needs exactly (farms + 1) rows. A header without `#` is counted as a row and gives `DISTANCES_KM needs N rows (Depot and every farm), found N+1`. The dashboard writes the header as a comment for you.
- Mistakes are reported with the line number and what to fix, e.g. `input error (line 14): a farm row is: name road stop_minutes, then 3 milk amounts (one per milk type); found 5 values`.

## Output: the collection plan (same for both solvers)

```
MILK COLLECTION PLAN
====================
Result        : all milk can be collected
Vehicles used : 2 of 3
Total time    : 499.00 minutes (8 h 19 min)

Vehicle Truck_A (truck + trailer) - 232.00 minutes on the road (shift limit 480)
  Route with trailer             : Depot -> Rossi -> Bianchi -> Romano -> Ferrari -> Depot
  Truck compartment 1 (37.5 q)   : High_quality - 30 from Rossi, 7.5 from Bianchi   (37.5 of 37.5 q)
  ...
  Trailer compartment 2 (37.5 q) : Standard - 17.5 from Ferrari   (17.5 of 37.5 q)

Vehicle Truck_B (truck) - 267.00 minutes on the road (shift limit 480)
  Route                          : Depot -> Romano -> Russo -> Greco -> Depot
  ...
Not needed    : Truck_C
```

- A truck + trailer can also have `Truck-only trip : X -> F -> X   (trailer waits at X)` lines: the trailer is unhooked at X (the Depot or a farm on its route) and the truck makes that trip alone.
- Each compartment line says which milk type it carries, how much comes from which farm, and how full it ends up. `empty` means the compartment is not used.
- If no plan exists: `Result : NOT POSSIBLE - these vehicles cannot collect all the milk within the shift`.
- Quantities are in quintals (q), with up to 4 decimals. A farm that appears in two vehicles has its milk split between them.
- `checker` reads this plan back, so it must not be edited by hand before checking.
- The dashboard reads this exact text format. If the printer in `milk_io.h` changes, `parsePlan` in `ui/index.html` must be updated too.

Sample (`sample.txt`, both solvers): 2 vehicles, 499 minutes. The optimum splits farm Romano by milk type: High_quality goes on Truck_A and Sanitary on Truck_B. That split saves a third vehicle. (The two solvers may print different but equally good routes and splits.)

## Exact algorithm (`exact.cpp`)

1. **Route cost for every possible set of farmers, exactly.**
   - Held-Karp from the depot gives the cheapest tour over every subset: O(2^n n^2).
   - For complete vehicles, take A = the S_tr farmers on the main tour and B = the S_wt farmers. The cheapest covering of B by subtours, each parked at the depot or at a farmer of A, comes from a subset-partition DP over Held-Karp tables built from every possible root: O(2^|Str| 3^|Swt| + n * 2^|Swt| * |Swt|^2).
   - Sets that break the shift get cost infinity.
2. **Branch and bound over which farmers each vehicle serves.**
   - Each vehicle's options are sorted by cost, and the bound is the lexicographic (vehicles, time).
   - A farmer may be served by several vehicles, which covers split pickup.
3. **Exact capacity check at each leaf that improves on the best so far.**
   - Search over milk-type assignments to compartments. Identical compartments are symmetry-broken.
   - For every type, a max-flow (farmers -> compartments they may reach) proves the milk fits. It is also used as a pruning bound while compartments are being assigned.
   - Leaving a compartment empty is never better than typing it, so empty is only used for compartments no remaining milk can reach.

Worst-case time is O((2^n)^V x (m^K max-flows)). Space is O(2^n n + 2^|Str| * 2^|Swt|). Measured: <= 2 s up to n about 8-9 with V <= 4, and 28 s at n = 10, V = 3. The hard limit is 16 farmers with milk.

## Heuristic (`heuristic.cpp`)

The paper's FRAP/RDP method needs a MIP solver (CPLEX). In its place, this is a self-contained Adaptive Large Neighbourhood Search on the same model.

**Capacity per vehicle.** Each vehicle's compartment typings are listed once and only the Pareto-maximal ones are kept. A vehicle's load fits iff some typing has, for every type, S_wt milk <= typed truck capacity and all milk <= typed total capacity. This follows from Hall's theorem, so no flow is needed.

**Insertion.** For each vehicle:
- the cheapest route position: tour position, subtour position, a new subtour at the best parking spot, or a zero-pickup S_tr "anchor" when an empty complete vehicle has to satisfy A4;
- the most milk it can absorb.

Two placement plans are built and the cheaper is kept: one vehicle taking everything, or a cheapest-per-quintal split over several vehicles. Opening an unused vehicle costs more than any possible time saving, which gives the lexicographic objective.

**Ruin & recreate.**
- Ruin removes random farmers, related farmers (nearest to a seed farmer), or a whole route (for fleet reduction). About 5% of the time it removes everything, a multistart-style restart.
- Recreate uses regret-2 or random order, with 20% cost noise half the time.

**Route improvement.** 2-opt and Or-opt on the tour and the subtours, then greedy re-parking of the subtours.

**Acceptance.** Fewer unserved farmers or fewer vehicles is always accepted. At equal counts, simulated annealing on time. The search restarts from the best solution after 2000 iterations without improvement and stops after the time limit or 30000 iterations without improvement.

**Complexity.** One iteration is O(k * V * (L*m + route length)) for k removed farmers and L Pareto typings per vehicle. Memory is O(n*V*m + sum L). Measured: about 15k iterations per 10 s at 50 farms and 13 vehicles, under 5 MB.

## Test results

- `edge_tests.sh`: 55/55 pass (23 cases x 2 solvers, plus 9 checks that the checker rejects broken plans). Re-run and confirmed on the final code.
- `sample.txt`: both solvers give 2 vehicles, 499 minutes, and the checker returns `OK 2 499.0000`.
- Dashboard: Solve was run through the live server for both solvers on `sample.txt`, and the checker verdict came back `OK 2 499.0000` each time.
- `run_tests.sh 300 0.5` (last recorded run), with n=3..8, V=2..4, m=1..3:
  - 247 feasible and 53 infeasible instances;
  - the heuristic matched the proven optimum on 244 of the 247 feasible ones;
  - it agreed on all 53 infeasible ones, never beat the exact solver, and every one of the 600 outputs passed the checker.
- The 3 misses are 1.3%, 3.2%, and one case with +1 vehicle. All three need a precise 3-way split of one farmer's milk across partly filled compartments, which greedy insertion doesn't build.
- Case-study scale (`gen 7 50 paper`, the paper's 13-vehicle fleet), last recorded run: valid solution with 7 of 13 vehicles in 10 s.

## Assumptions and limitations

- Distances must be symmetric and non-negative. Shortest paths are taken first (Floyd-Warshall), so passing a farm without stopping costs nothing extra.
- Preparation time is counted once per (vehicle, farmer) visit, so split pickups pay it twice, as in the paper's RDP objective. Coupling and uncoupling the trailer takes no time.
- Farmers with zero milk are not visited for pickup (the paper's A3 would force a visit, which only adds time). A `trailer_ok` farm with no milk can still be used as a parking stop for truck-only trips.
- Parking is allowed only at the depot or at an S_tr farmer on the same vehicle's main tour, and subtours never visit S_tr farmers. These are the paper's own restrictions.
- (A4) is followed literally: a used complete vehicle must visit at least one S_tr farmer, even if it picks up nothing there.
- There are no time windows, stochastic yields, or multi-day planning, as in the paper.
- The heuristic gives no optimality bound. Its typing enumeration assumes up to about 8 compartments per vehicle.
- The dashboard is a local tool: it solves one day at a time, does not save scenarios (use Export input .txt), and has no route map.
